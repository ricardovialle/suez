Usage guide

Every way to run suez

Inputs, the two steps, and one section per study design, then inference and running at scale. Every code block on this page runs as written: it is checked by Rscript doc/src/examples.R.

The first sections use the example study bundled with the package (60 individuals × control and treated, RNA-seq counts, a VCF). Designs that study does not have (time courses, doses, ages, unbalanced visits, admixture) use a simulated table meta with one row per sample, expr (genes × samples), geno (SNPs × individuals) and their snploc_t / geneloc_t, or the bundled admixed cohort.

Getting started

Install

# install.packages("pak")
# pak::pak("ricardovialle/suez")
# pak::pak(c("VariantAnnotation", "GenomicRanges", "IRanges"))   # only to read VCFs
library(suez)
library(doMC); registerDoMC(4)            # genes run in parallel on 4 forked workers

Needs a C++17 compiler (Xcode command line tools, Rtools, or g++/clang). Dependencies, including rstan and StanHeaders ≥ 2.26, install automatically. On Windows use doParallel::registerDoParallel() instead of doMC.

Step 1: learn the sample covariance

anno = data.frame(individual = samples$individual, condition = samples$condition)
qq = t(apply(logcpm, 1, function(x) qnorm((rank(x) - 0.5) / length(x))))   # normal scores per gene

Z = scale(t(dosage)); Z[is.na(Z)] = 0          # GRM; in a real study: genome-wide, LD-pruned SNPs
grm = tcrossprod(Z) / ncol(Z)

set.seed(1)
step1 = learn_covariance(qq, anno, kinship_matrix = grm, P = 10)
step1$optimized_fit$return_code                # 0: the optimizer converged
round(step1$optimized_fit$par$s, 3)            # noise, same-individual and kinship variances

What step 1 learned

Fitted variances: noise, same-individual, kinship and the largest latent factors
Learned covariance, first 16 samples: each individual's two samples form a block

  • Use all expressed genes, normalized (here: normal scores per gene), not only the ones you will test.
  • P is the number of latent factors. Unneeded factors shrink towards zero variance, so a generous P (10 to 20) is usually safe.
  • kinship_matrix is optional: an individuals × individuals GRM with names matching anno$individual. Build it from genome-wide, LD-pruned SNPs.
  • Check convergence: return_code == 0; otherwise pass a larger iter =.
  • Skip step 1 and suez uses a same-individual kernel only. It is exact and fast at any N, but does not model hidden confounders or relatedness.

Step 2: map eQTLs and response eQTLs

The main arguments, with their defaults:

Study designs

One section per design

The design only changes anno$condition, and sometimes the kernel or covariates. The tests and output stay the same.

eQTL mapping, one sample per individual

condition = 1p_geno onlybundled data
ctrl = samples$condition == "control"          # one sample per individual
anno_ctrl = data.frame(individual = samples$individual[ctrl], condition = 1)   # one value: eQTL tests only

                               sample_kernel = grm[anno_ctrl$individual, anno_ctrl$individual])
summary(res_ctrl$p_interact)                   # all NA: no interaction terms

What is measured: one eQTL

0 ALT12group mean

A single value of condition drops the interaction terms. With one sample per individual and unrelated donors, a GRM kernel (or step 1 with kinship_matrix) keeps the eQTL test calibrated when there is relatedness or structure; otherwise the result is close to a linear regression.

What suez detects: a response eQTL

0 ALT12group mean
Expression at the lead SNP, by genotype, in each condition
Every cis-SNP of the gene; the grey bar is the gene body

The standard response-eQTL design: each donor measured before and after a treatment. Both samples of a donor share the random effect, so suez uses all samples instead of a per-donor difference (which doubles the noise and allows only two conditions). beta_geno is the genotype effect averaged over conditions.

A time-dependent eQTL

0 ALT12group mean

One joint test of whether the genotype effect differs between any of the levels. The first factor level is the reference; the test itself does not depend on which level that is. For a dose series or ordered times where a trend is the question, use a numeric or spline condition instead.

A dose-dependent eQTL

0 ALT12

β(condition) = β0 + β1·condition. Transform the condition so a straight line is plausible (here log dose). Rescaling it does not change the p-values.

Smooth condition: effects that bend

splines::ns(x, df)p_interact, dfcurve_atsimulated
B = splines::ns(meta$age, df = 3)              # natural-spline basis of age, 3 columns
anno_age = data.frame(individual = meta$individual)
anno_age$condition = B
ages = seq(30, 85, 5)
at = predict(B, ages); rownames(at) = ages     # evaluate the same basis on a grid of ages
res_age = map_interaction_qtl(expr, geno, geneloc_t, snploc_t, anno_age, curve_at = at)
hit = res_age[which.min(res_age$p_interact), ]
round(rbind(beta = unlist(hit[paste0("beta_curve_", ages)]),
            se   = unlist(hit[paste0("se_beta_curve_", ages)])), 2)

The fitted curves

planted β(age)splinelinear age term95% CI
β(age): eQTL effect per ALT allele
μ(age): the gene's age trajectory, relative to age 30

Both the expression trajectory μ(age) and the eQTL effect β(age) become smooth curves, and p_interact jointly tests all genotype × basis terms. With curve_at you get, per grid point, beta_curve_x, se_beta_curve_x, mu_curve_x and se_mu_curve_x. Evaluate the basis with predict() on the same ns object so the knots match. Choose df (2 to 4) by the spread of the condition, not by fit. The age-varying eQTL report compares this with the linear model.

Losing samples, not individuals

planted response SNPother SNPs

Nothing special is needed: anno lists the samples you have. Individuals with one sample still inform the eQTL test, and the same-individual term handles the rest. A per-donor difference would have to drop every donor with a missing sample.

What a covariate buys

planted SNPother SNPs

Fixed effects in every model: genotype PCs, sex, batch, RIN, global ancestry. One row per sample in the order of anno. Hidden confounders do not need to go here: step 1's latent factors model them as part of the random effect.

Related individuals and hidden confounders

kinship_matrixsample_kernelsimulated

Two kernels for the same samples

positive covariancenegative
Learned by step 1: GRM + same individual + latent factors
A GRM expanded to samples: repeated samples share their individual's row

Both kernels put the three samples of an individual in one block. Step 1 adds the latent factors, which spread covariance between individuals who share a hidden confounder.

Without a relatedness term, related individuals inflate the tests. The calibration results show the same effect for repeated samples analysed as independent ones.

Phase the genotypes, call local ancestry (RFMix2 or FLARE) and run Tractor's extract_tracts.py; read_tractor() reads the per-ancestry dosage and haplotype-count files. Each SNP is fitted with six nested models:

TestModelsQuestion
p_genoM1 vs M0Any eQTL effect, on any ancestry (df = number of ancestries)
p_hetM1 vs M1sDo the eQTL effects differ between ancestries?
p_interactM2 vs M1cAny response eQTL, on any ancestry
p_interact_hetM2 vs M2sDo the responses differ between ancestries?
beta_<anc>, p_<anc>Wald, M1Effect per ALT allele on that ancestry's haplotypes
p_interact_<anc>Wald, M2That ancestry's response (a joint F test for several condition columns)
Tag SNPs. LD that differs between ancestries makes effects look different at SNPs that only tag the causal variant. Fine-map before interpreting p_het away from the lead SNP. Keep the GRM in step 1: it does not absorb ancestry-specific effects, and leaving it out inflates the tests in related samples.
Inference

Multiple testing

gene_level = function(res, p) {                # Bonferroni within gene, then BH across genes
  top = do.call(rbind, lapply(split(res, res$gene), function(d) {
    i = which.min(d[[p]])
    data.frame(gene = d$gene[i], snp = d$cis_snp[i], p = d[[p]][i], p_gene = min(1, d[[p]][i] * nrow(d)))
  }))
  top$fdr = p.adjust(top$p_gene, "BH")
  top[order(top$p), ]
}
egenes  = gene_level(res, "p_geno")
regenes = gene_level(res, "p_interact")
c(eGenes = sum(egenes$fdr < 0.05), response_eGenes = sum(regenes$fdr < 0.05))

Gene-level calls

eQTL testresponse test

p-values are per SNP. A simple gene-level procedure: Bonferroni within each gene, then Benjamini-Hochberg across genes. For fine-mapping or colocalisation, export the per-SNP statistics.

Checking calibration and the bootstrap

lambda = function(p) median(qchisq(p, 1, lower.tail = FALSE), na.rm = TRUE) / qchisq(0.5, 1)
c(geno = lambda(res$p_geno), interact = lambda(res$p_interact))   # close to 1 when calibrated

lr      = 2 * (res$l_interact - res$l_geno)              # observed interaction likelihood ratios
lr_null = 2 * (res$l_boot_interact - res$l_boot_geno)    # one bootstrap null draw per SNP
res$p_interact_boot = sapply(lr, function(x) mean(c(lr_null, Inf) >= x, na.rm = TRUE))

Are the p-values calibrated?

eQTL testresponse test

Most genes have no response eQTL, so λ of p_interact over all tests should be near 1. Each SNP's bootstrap columns give one draw of the interaction likelihood ratio under the genotype-only model. Pooled over a genome-wide run, they form an empirical null for the observed ratios (smallest possible p-value: 1 / (tests + 1)). In local-ancestry mode use l_boot_interact_null in place of l_boot_geno.

A permutation null run

c(geno = lambda(res_null$p_geno), interact = lambda(res_null$p_interact))

A null run

eQTL testresponse test

Shuffles individuals' genotypes within each gene: every test is null, which checks the whole pipeline end to end. Use it as a diagnostic, not for p-values: a permutation is not a valid null for the interaction test, where the genotype main effect must be kept.

Running at scale

Parallel workers, threads and checkpoints

library(doMC); registerDoMC(8)                 # 8 forked workers (doParallel on Windows)
options(suez.threads = 2)                      # and 2 threads per gene: 16 CPUs in all
set.seed(1)                                    # same results on any number of workers or threads
res_par = map_interaction_qtl(logcpm, dosage, geneloc, snploc, anno, sample_kernel = step1$cov_suez,
                              permutation_approach = "none",            # skip the bootstrap: ~1/3 faster
                              checkpoint_dir = file.path(tempdir(), "suez_ckpt"))   # resumable
options(suez.threads = 1)

Speed-up with forked workers

Step 2, measured on the benchmark workloads; the dashed line is perfect scaling. The dense-GRM workload at 2,000 samples (XL_grm) scales least; for large kernels, threads reach similar speed with far less memory.

  • Workers (doMC forks) are fastest; threads share one process's memory: with a GRM at 2,000 samples, 1 process × 8 threads ran at about 75% of the speed of 8 workers with a quarter of their RAM.
  • Reproducible: each gene draws its seed from your session, so after set.seed() results are identical for any number of workers or threads.
  • Checkpoints are reused as they are: delete the directory after changing data or arguments.
  • Memory: step 1 and an explicit kernel are N × N. The default same-individual kernel is built analytically and stays light at thousands of samples.

Splitting a genome-wide run

for (chr in unique(geneloc$chr)) {             # or one cluster job per chromosome
  out = map_interaction_qtl(logcpm, dosage, geneloc[geneloc$chr == chr, ], snploc, anno,
                            sample_kernel = step1$cov_suez)
  readr::write_tsv(out, file.path(tempdir(), paste0("suez_", chr, ".tsv.gz")))
}

Subset geneloc to split the work, one chromosome per job on a cluster. suez does not write results itself; save each part. In local-ancestry mode, read one chromosome of Tractor files at a time.
